# Discipline and Consistency in Practice: Troubleshoot, Restart, and Stop

If you have read the methods but still cannot start, or have stopped for two weeks and do not know how to resume, choose one concrete problem here. This is an adjustable practice guide, not a validated behavioral intervention or a promise that a habit will form within a fixed number of days.

For capacity, environment, and boundaries, consult [Daily Systems](../part-4/daily-system.md). For repetition, feedback, and interruptions, see [Rhythm and Compounding](../part-4/rhythm-and-compounding.md). For decisions across cycles, see [Action and Long-Term Change](../part-5/long-term-action.md). This guide does not introduce another daily system. It turns those methods into one action experiment with an end date.

## First Find Where the Process Breaks

Open a recent, actual record and identify the missing step between planning and producing work. Do not settle for “procrastination,” and do not try to address the entire table at once.

| What you can observe | First check | Try one change this cycle | What to inspect |
| --- | --- | --- | --- |
| Other demands repeatedly displace the session | Whether you control the supposedly free time | Choose a genuinely available window or reduce the workload | Whether the window actually occurs |
| You open the computer without knowing what to do | Whether the next file and action are specified | Save the file location and first action in advance | Whether you can begin the task directly |
| Work continues without an endpoint | Whether acceptance criteria are too large or vague | Narrow the task to a recording, test, or question | Whether you can finish within the budget |
| Plans accumulate without additional work | Whether this week's saved files are plans or outputs | Stop adding plans and complete one existing task | Whether a reviewable first version exists |
| Much work is done, but the effect is unclear | Whether a baseline and consistent criteria exist | Check an earlier output using the same criteria | Which specific error has changed |
| An interruption makes you want to repay all missed work | Whether the original schedule remains valid | Drop expired arrangements and prioritize this week again | Whether existing responsibilities remain protected |
| The routine relies on overtime or broken commitments | Whether costs exceed the budget | Reduce scope, negotiate the deadline, or pause | Whether the cost becomes manageable |

The table offers possible causes to test, not diagnoses of a person. A new app may not help when you cannot control your time. If the goal has lost its purpose, further optimization may be unnecessary.

## Example One: Many Plans, but No Start

**This example is fictional. Dates, durations, and results illustrate the method and do not promise an outcome.** A working learner wants to explain an AI tool in English during a team discussion. They have collected English courses, prompting tutorials, and development roadmaps.

**Original plan.** Study English for an hour and AI for an hour every evening, then organize the notes into a complete knowledge base on the weekend. “Finish learning” has no clear definition, and the schedule leaves no room for family responsibilities.

**Evidence of failure.** A week produces five schedules and more than a dozen open course pages, but no recording or runnable example. Reviewing the calendar shows that evenings are unpredictable. The available time consists of two 20-minute lunch breaks and 15 minutes on Sunday. The first changes needed concern scope and the starting point; these records do not establish a lack of learning ability.

**Smallest change.** This week, explain only the tool's purpose and one limitation, using an existing one-page outline. Write three points during the first lunch break. During the second, find a place where speaking is practical, record a 60-second introduction, and listen back. On Sunday, correct one point and record again. The total budget is 55 minutes, including preparation and feedback. Add no new courses. End each session by saving the file location and next step.

**One-week review and stopping conditions.** Compare the recordings for clarity about purpose and limitations. If a colleague is willing to provide feedback, ask them to restate what they heard. If no listener is available, mark external feedback as missing; AI praise cannot fill that gap. If the windows disappear again, keep only one point or pause. If the team no longer needs the introduction, reassess its purpose before continuing.

An illustrative first-week result might be that both recordings exist and the second states a limitation, but a listener still misunderstands the intended user. Next week, change only the sentence explaining who the tool serves. If the week instead produces another plan without a first version, examine whether the first action remains too large rather than adding another schedule. This small sample describes the task; it does not demonstrate an overall improvement in English ability.

## Example Two: Restarting This Week After a Two-Week Break

**This example is also fictional.** After moving home, a learner wants to resume an AI document-retrieval prototype. Six new features remain on the old task list.

**Original plan.** Complete everything missed during the move by Sunday, then return to the original development pace. The old records do not explain how to run the project or preserve a baseline for retrieval correctness.

**Evidence of failure.** The project has not run for two weeks, and the environment has changed. The claim that it “looked usable last time” exists only in a chat description, without a matching test. Available time is now two 30-minute windows and a 20-minute review: 80 minutes in total. The prototype's current state is unknown, so a six-feature commitment is not justified.

**Smallest change.** Use the first window only to restore the existing run procedure and record commands, the current version, and actual errors. During the second, prepare up to five small examples using documents the learner is entitled to use. Save each question, source, manually checked expected result, and actual result. Spend the final 20 minutes reviewing the evidence and deciding which error to address first. Freeze new features and do not label unfinished examples as verified.

**One-week review and stopping conditions.** This cycle delivers a reproducible state record and comparisons for the examples actually completed. It does not require improved accuracy, and five examples cannot establish general reliability. If environment repair exhausts its time limit, save the blocker and needed help, then stop without taking time from other responsibilities. If necessary data or authorization is missing, pause the affected work until the condition is resolved.

Suppose the learner restores the project and checks only three examples, one of which fails. The record should say “three checked, one failed,” with the other two still pending. Next week, investigate the failure before deciding whether to expand the sample. If the original need has disappeared, preserve the run instructions and useful work, then end this project cycle. Time already spent does not independently justify further work.

## Make the Next Action a Small Experiment

Choose one row from the troubleshooting table. In the [Consistency Plan](../../templates/consistency-plan.md), record the current evidence, one change, effort limit, intended output, and criteria for next week's decision. The template supplements the [Rhythm Ledger](../../templates/rhythm-ledger.md) with a single action experiment. If you already maintain a ledger, reference its relevant records instead of copying everything.

When stopping, preserve the file location, unresolved issue, and review condition. At review time, return the conclusion to the ledger or [Weekly Review](../../templates/weekly-review.md), keeping only changes that proved useful. Reduce the workload as soon as conditions require it; there is no need to accumulate a fixed number of failures. When restarting, check the current facts rather than compensating for every missed session.
